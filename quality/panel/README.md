# Панель спикеров — протокол

Две **непересекающиеся** панели. Спикер состоит ровно в одной, навсегда.

| | product-панель | bench-панель |
|---|---|---|
| Назначение | dev/eval для продуктовых решений (потоки C/D/F, ступени лестницы) | public + hidden сеты DictationBench |
| Размер | ≥12 спикеров | 6–8 (EN 2–3, RU 2–3, CS 2) |
| Публикация | никогда; хранится локально | public-сет публикуется под CC-BY 4.0 |
| Согласие | `consent-product-ru.md` | `consent-bench-ru.md` (CC-BY!) |
| Куда нельзя | в трейн любых моделей — только dev/eval | в трейн и в продуктовые dev/eval — никуда, кроме бенча |

Правила файрвола (нарушение = недействительный результат):
1. Голоса hidden-сета не попадают ни в какие трейн/eval данные моделей. Никогда.
2. Голоса public-сета не попадают в трейн.
3. Реальные часы для ASR-адаптера (ступень 3) записываются отдельно и speaker-disjoint от обеих панелей.
4. Сплиты по спикерам фиксируются в ступени 0 и не пересматриваются.
5. Смоук-гейт релиза (5 «своих» спикеров) — отдельный набор, в панели не входит, никуда кроме `quality/live-benchmark.json` не идёт.

## Запись

- Тихая комната; два прогона на спикера: встроенный микрофон Mac и внешний/bluetooth (как в `live-benchmark-template.json`).
- Спикер читает скрипт из `scripts/` (референс = текст скрипта, замораживается до скоринга) + 2–3 минуты спонтанной речи на заданную тему (референс расшифровывается вручную и замораживается).
- Формат: WAV 16 кГц mono (или m4a с конвертацией `afconvert -f WAVE -d LEI16@16000 -c 1`).
- Имена файлов: `<panel>-<speaker-id>-<script>-<mic>.wav`, например `prod-s03-mixed-builtin.wav`. Без настоящих имён людей.
- Словарь приложения при записи гейта — пустой (`emptyUserDictionary: true`).

## Смоук live-benchmark (день 0–1)

1. 5 своих спикеров читают `scripts/smoke-ru.txt`, `smoke-en.txt`, `smoke-mixed.txt` (оба микрофона).
2. Референсы = тексты скриптов; зафиксировать `referencesFrozenAt` ДО первого прогона через приложение.
3. Прогнать клипы, посчитать метрики скорером `asr-bench`, заполнить `quality/live-benchmark.json` по шаблону.
4. Валидация: `python3 scripts/validate-live-benchmark.py`.
5. Решение по движку: провал >3 пп на mixed → см. failure-tree в `docs/sprint-sota-30.md`.
