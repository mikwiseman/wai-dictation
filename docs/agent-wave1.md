### 3.7 Babble-guard
**Что.** Не вставлять молча речь посторонних.
**Где.** `Packages/DictationAudio` (энергия/SNR считается там же, где уровень для HUD), решение — чистый тип в `DictationCore`.
**Как.** Сначала замерить частоту обрыва на babble-корпусе (§2), потом выбирать сигналы: SNR, доля кадров с перекрытием, энергия фона. **Язык результата сигналом не является** — code-switching для нашего пользователя норма. При срабатывании — не тихая вставка, а нотис с выбором «вставить / отменить».
**Гейт.** На babble-корпусе ловится ≥90% случаев, на чистом ложных срабатываний ≤2%.

## 4. Продуктовые решения — уже приняты, не пересматривать

- Только macOS. Никакого облака, ни в каком режиме, ни за какими флагами.
- Экран не читаем: единственный контекст — bundle id активного приложения.
- Apple Foundation Models не используем: русского нет до OS 27, адаптер привязан к версии системной модели.
- Модель одна, зоопарка вариантов не будет.
- По умолчанию на диск не пишется ничего; всё, что пишется, — за явным тумблером с кнопкой удаления.
- Красный гейт = не выпускаем. Пост про модель в этом случае превращается в разбор «где чистка окупается, а где нет» — это допустимый и планируемый исход, а не провал.

## 6. Заблокировано на человеке — не эмулируй

- Живой смоук (5 человек, скрипты `quality/panel/scripts/`) → `quality/live-benchmark.json`. Это релиз-блокер; `release.sh` без файла падает намеренно.
- Панели спикеров (внутренняя ≥12, публичная 6–8 с согласием CC-BY) — датасет бенчмарка и финальные замеры.
- Подпись, нотаризация, публикация постов.

Что делать с этим: готовь всё так, чтобы подключение сводилось к добавлению файлов. Артефакты синтетических прогонов складывай отдельно и всегда с пометкой `synthetic`. **Не подставляй синтетические цифры в `quality/live-benchmark.json`** — этот файл существует ровно для того, чтобы отличать измеренное на людях от измеренного на `say`.
